TECHNICAL CONCEPT PAPER / D0.1

ROOT: A local architecture for room-level AC comfort

ROOT is a proposed controller for IR-operated split air conditioners. Its design thesis is to sense conditions closer to an occupied location, make bounded control decisions on the device, and transmit adjustments through the AC's existing infrared interface. This paper describes the intended architecture and how it should be evaluated. It does not report product performance.

01 / PROBLEM

The occupied part of a room can differ from the return-air reference.

Cited background CB-01

Split air conditioners typically regulate from a temperature reference near the indoor unit. Airflow, heat loads, room geometry, and occupant location can create non-uniform conditions that a single reference does not fully describe. Recent experimental work has examined non-uniform cooling and the limits of a single thermostat reference in split-AC rooms.1

ROOT's design hypothesis is narrower: a sensor placed near a bed, couch, or desk may provide a more relevant control input for that location. The magnitude and usefulness of any difference remain dependent on the room and must be measured.

02 / ARCHITECTURE

A four-stage loop with a deliberately small control boundary.

Hypothesis / design target HT-01
  1. 01

    Sense

    Sample temperature, humidity, and a bounded presence signal near the intended occupied location.

  2. 02

    Interpret

    Estimate whether the configured control context is active without treating presence as health or vital-sign monitoring.

  3. 03

    Decide

    Apply local rules with bounded setpoints, bounded command rates, manual override, and a neutral fallback.

  4. 04

    Transmit

    Send an infrared command using the learned AC interface. An emitted command is not treated as confirmed AC state.

03 / CONTROL BOUNDARY

Local control is a scoped pathway, not a blanket privacy or uptime claim.

Hypothesis / design target HT-02
Initial setup
Bluetooth is a proposed configuration pathway. Exact permissions, pairing authorization, and retained identifiers require a reviewed data-flow design.
Remote learning
The intended setup records supported IR commands from the existing AC remote. Compatibility must be demonstrated per model and command set.
Sensing and decision
The intended core loop runs on the device after configuration. This boundary does not include every future app, update, diagnostic, or support feature.
Network loss
Offline operation must be tested after setup through sensing, decision, command, reboot, and reconnection scenarios.
Data boundary
A future Bluetooth proximity feature may process a paired identifier and received signal strength. Storage, retention, deletion, reset behavior, sharing, and location permissions are not yet assigned.

Bluetooth received signal strength varies with device orientation, obstruction, radio conditions, and implementation. It should be treated as a coarse input and not the sole basis for a safety-relevant or irreversible action.2

04 / INTERFACE

Sensing and infrared are system elements awaiting integrated validation.

Hypothesis / design target HT-03

Climate input

Temperature and humidity are proposed control inputs. Part specifications and display resolution do not establish integrated system accuracy.

Presence input

The proposed signal is limited to room-control context. It must not be described as breathing, sleep, fall, health, or vital-sign monitoring.

Infrared learning

Learning must record supported commands without implying broad compatibility. Unknown, ambiguous, or incomplete state should produce a neutral outcome.

Infrared transmission

Reach depends on orientation, distance, line of sight, surfaces, emitter configuration, and the receiving AC. Coverage remains a test question.

05 / PLACEMENT

Placement changes what the device can sense and reach.

Hypothesis / design target HT-04

Tabletop, nightstand, couch-side, desk-side, and wall-mounted arrangements are placement concepts, not equivalent operating modes. Each changes sampled air, exposure to drafts or heat sources, sensor obstruction, mounting stability, occupant proximity, and the IR path to the AC.

Placement guidance must therefore be tied to tested room and AC configurations. The user should retain access to manual AC controls when the recommended position cannot provide a reliable sensing or transmission path.

06 / EVALUATION

Report protocols before results.

Every evaluation should identify the hardware and firmware revision, conditions, comparator, ground truth, sampling, repeated trials, primary outcome, acceptance rule, exclusions, uncertainty, and retained evidence artifact.

Planned evaluationPE-01

Climate sensing

Co-locate ROOT with a traceable reference logger. Report bias, mean absolute error, repeatability, sampling interval, stabilization time, and uncertainty.

Planned evaluationPE-02

Presence sensing

Compare detections with timestamped ground truth across occupied, unoccupied, stationary, moving, obstructed, and false-trigger scenarios.

Planned evaluationPE-03

IR interoperability

Test a declared sample of AC models and commands over repeated trials, distances, angles, and line-of-sight conditions. Report failures by model.

Planned evaluationPE-04

Offline operation

Disable Wi-Fi and internet after setup. Exercise sensing, decisions, commands, reboot, and reconnection for a declared duration.

Planned evaluationPE-05

Setup

Observe first-time users completing one defined flow. Report completion, assistance, retries, failure reasons, and timing distributions.

Planned evaluationPE-06

Power behavior

Measure nominal and peak draw, supported input conditions, brownout and restart behavior, and recovered state.

Planned evaluationPE-07

Room comfort stability

Compare a declared baseline with ROOT under recorded room, placement, AC, outdoor, load, and occupancy conditions. Predefine deviation, overshoot, cycling, and humidity outcomes.

07 / BOUNDARIES

A comfort controller with explicit limits.

Controlled disclosure CD-01

Intended use

ROOT is intended for general room-comfort control. It is not a medical device and is not intended to diagnose, prevent, monitor, predict, mitigate, or treat disease, injury, disability, a physiological condition, sleep, or a vital sign.

Safety role

ROOT is not a safety-critical, emergency, or life-support controller. Users must retain the original AC remote and access to the AC's manual controls.

Autonomous limits

Bounded setpoints, bounded command rates, visible fault indication, manual override, and a neutral fallback remain design targets until implemented and tested.

Failure conditions

Validation must cover sensor faults, stale inputs, proximity loss, ambiguous IR state, blocked line of sight, AC non-response, power interruption, conflicting preferences, mounting failure, and optional-connectivity loss.

Compatibility

Behavior depends on AC hardware, room geometry, placement, obstruction, environmental conditions, power, firmware, and operating mode. No compatibility result is reported here.
